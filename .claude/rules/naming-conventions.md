# Naming Conventions

## File Naming Standards

### Frontend (Next.js / React)

**Components:**

- Use `PascalCase.tsx` for React components
- Examples: `ContactCard.tsx`, `DealPipeline.tsx`, `UserAvatar.tsx`

**Pages/Routes (App Router):**

- Use `kebab-case` for route folders and files
- Examples: `app/contacts/page.tsx`, `app/deals/[id]/page.tsx`

**Hooks:**

- Use `camelCase.ts` with `use` prefix
- Examples: `useContactForm.ts`, `useTextToSql.ts`

**Utilities/Helpers:**

- Use `kebab-case.ts`
- Examples: `string-utils.ts`, `date-formatter.ts`, `api-client.ts`

**Types:**

- Use `PascalCase.types.ts` for type definition files
- Examples: `Contact.types.ts`, `Deal.types.ts`, `ApiResponse.types.ts`

**Constants:**

- Use `SCREAMING_SNAKE_CASE.ts` for constant files
- Examples: `API_ENDPOINTS.ts`, `QUERY_KEYS.ts`

### Backend (NestJS)

**Controllers:**

- Use `kebab-case.controller.ts`
- Examples: `contact.controller.ts`, `text-to-sql.controller.ts`

**Services:**

- Use `kebab-case.service.ts`
- Examples: `contact.service.ts`, `prisma.service.ts`

**Modules:**

- Use `kebab-case.module.ts`
- Examples: `contact.module.ts`, `auth.module.ts`

**DTOs (Data Transfer Objects):**

- Use `kebab-case.dto.ts`
- Examples: `create-contact.dto.ts`, `update-deal.dto.ts`

**Entities/Models:**

- Use `kebab-case.entity.ts` or `kebab-case.model.ts`
- Examples: `contact.entity.ts`, `deal.model.ts`

**Guards:**

- Use `kebab-case.guard.ts`
- Examples: `jwt-auth.guard.ts`, `roles.guard.ts`

**Interceptors:**

- Use `kebab-case.interceptor.ts`
- Examples: `logging.interceptor.ts`, `transform.interceptor.ts`

**Pipes:**

- Use `kebab-case.pipe.ts`
- Examples: `validation.pipe.ts`, `parse-uuid.pipe.ts`

### Shared Packages

**Types:**

- Use `PascalCase.types.ts`
- Examples: `packages/types/Contact.types.ts`

**Utilities:**

- Use `kebab-case.ts`
- Examples: `packages/utils/string-utils.ts`

**Configuration:**

- Use `kebab-case.config.ts`
- Examples: `packages/config/database.config.ts`

### Tests

**Unit Tests:**

- Use same name as source file with `.spec.ts` suffix
- Examples: `contact.service.spec.ts`, `ContactCard.spec.tsx`

**Integration Tests:**

- Use `.integration.spec.ts` suffix
- Examples: `contact.integration.spec.ts`

**E2E Tests:**

- Use `.e2e.spec.ts` suffix
- Examples: `contact-flow.e2e.spec.ts`, `text-to-sql.e2e.spec.ts`

### Database

**Prisma Migrations:**

- Auto-generated by Prisma with timestamp
- Format: `YYYYMMDDHHMMSS_descriptive_name`
- Examples: `20260505120000_add_contact_table`, `20260505130000_add_tenant_isolation`

**Seed Files:**

- Use `kebab-case.seed.ts`
- Examples: `contacts.seed.ts`, `users.seed.ts`

## Folder Naming Standards

### General Rules

- Use `kebab-case` for all folder names
- Be descriptive but concise
- Group related files together

## Variable & Function Naming

### TypeScript/JavaScript

**Variables:**

- Use `camelCase`
- Be descriptive
- Examples: `contactList`, `isLoading`, `userEmail`

**Constants:**

- Use `SCREAMING_SNAKE_CASE` for true constants
- Examples: `MAX_RETRY_ATTEMPTS`, `API_BASE_URL`, `DEFAULT_PAGE_SIZE`

**Functions:**

- Use `camelCase`
- Start with verb
- Examples: `getContact()`, `createDeal()`, `validateEmail()`

**Boolean variables/functions:**

- Prefix with `is`, `has`, `should`, `can`
- Examples: `isValid`, `hasPermission`, `shouldRetry`, `canEdit`

**Event Handlers:**

- Prefix with `handle` or `on`
- Examples: `handleSubmit`, `onContactClick`, `handleFormChange`

**React Components:**

- Use `PascalCase`
- Examples: `ContactCard`, `DealPipeline`, `UserAvatar`

**Custom Hooks:**

- Prefix with `use`
- Examples: `useContactForm`, `useAuth`, `useTextToSql`

### Database (Prisma Schema)

**Models:**

- Use `PascalCase` singular
- Examples: `Contact`, `Deal`, `User`

**Fields:**

- Use `camelCase`
- Examples: `firstName`, `createdAt`, `tenantId`

**Relations:**

- Use descriptive names
- Examples: `contacts`, `deals`, `assignedTo`

**Enums:**

- Use `PascalCase` for enum name
- Use `SCREAMING_SNAKE_CASE` for values
- Examples:
  ```prisma
  enum DealStatus {
    OPEN
    IN_PROGRESS
    WON
    LOST
  }
  ```

## GraphQL Naming (Pothos)

**Types:**

- Use `PascalCase`
- Examples: `Contact`, `Deal`, `QueryResult`

**Fields:**

- Use `camelCase`
- Examples: `firstName`, `createdAt`, `dealValue`

**Queries:**

- Use `camelCase`
- Start with verb or noun
- Examples: `contact`, `contacts`, `searchDeals`

**Mutations:**

- Use `camelCase`
- Start with verb
- Examples: `createContact`, `updateDeal`, `deleteUser`

**Input Types:**

- Suffix with `Input`
- Examples: `CreateContactInput`, `UpdateDealInput`

## REST API Naming

**Endpoints:**

- Use `kebab-case`
- Use plural nouns for resources
- Examples: `/api/contacts`, `/api/deals`, `/api/text-to-sql/query`

**Query Parameters:**

- Use `camelCase`
- Examples: `?pageSize=10`, `?sortBy=createdAt`, `?tenantId=123`

## Environment Variables

**Format:**

- Use `SCREAMING_SNAKE_CASE`
- Prefix by category
- Examples:
  ```
  DATABASE_URL
  REDIS_HOST
  REDIS_PORT
  VERTEX_AI_PROJECT_ID
  VERTEX_AI_LOCATION
  SUPABASE_URL
  SUPABASE_ANON_KEY
  NEXT_PUBLIC_API_URL
  ```

**Prefixes:**

- `DATABASE_` - Database related
- `REDIS_` - Redis related
- `VERTEX_AI_` - Vertex AI related
- `SUPABASE_` - Supabase related
- `NEXT_PUBLIC_` - Public frontend variables (Next.js convention)

## Critical Rules for AI Agents

1. **Consistency is key** - Always follow the same pattern within a category
2. **Be descriptive** - Names should clearly indicate purpose
3. **Avoid abbreviations** - Use full words unless industry standard (e.g., `dto`, `api`, `id`)
4. **No spaces or special characters** - Use hyphens or camelCase
5. **Follow framework conventions** - NestJS uses kebab-case, React uses PascalCase for components
6. **Test files mirror source files** - `contact.service.ts` → `contact.service.spec.ts`
